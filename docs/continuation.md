# 続きを書く

書きかけの文の後ろで Shift+Tab を押すと、その先の 1〜2 文が薄い色で現れます。読んで、良ければ Tab で本文にします。違えばもう一度 Shift+Tab で別の案が出ます。何度出し直しても本文は変わりません。

書いているのは Mac の中のローカルモデルです。手が止まったときに一歩だけ先を見せてくれる、メールの決まり文句を打ち切る前に埋めてくれる、言い回しに迷ったときに一案出してくれる。そんな使い勝手を目指しました。IME の中にあるので、エディタでもブラウザでもチャットでも、文章を打てる場所ならどこでも同じキーで呼べます。

## 使い方

1. いつもどおり文章を打って確定する
2. 続きを書かせたい位置にカーソルを置いたまま **Shift+Tab** を押す
3. 「…」が出て、1〜2 秒で提案が薄い色で現れる
4. 次のどれかをする


| 操作              | 結果                 |
| --------------- | ------------------ |
| Tab または Enter   | 提案を本文に取り込む         |
| Shift+Tab（もう一度） | 別の提案を出し直す          |
| Esc             | 提案を捨てる             |
| 普通の文字を打つ        | 提案を捨てて、打った文字の入力に進む |


提案は取り込むまで本文に入りません。薄く見えているだけなので、気に入らなければ何度でも出し直せます。

未確定の文字列（下線付きの入力中の文字）がある状態で押すと、まずそれを確定してから続きを書きます。

## 例

「お世話になっております。先日はお打ち合わせの時間をいただき、」まで打って Shift+Tab を押すと、「ありがとうございました。本日はその際にご相談した件について、資料をお送りします。」のような続きが薄く表示されます。Tab で取り込めば、あとは必要なところだけ直せます。

常体で書いていれば常体で、敬体で書いていれば敬体で続けるよう指示しています。カーソルの前の最大 400 文字を見るので、段落の途中でも話題を追った続きになります。

## キー


| キー        | 用途                                                                                                                |
| --------- | ----------------------------------------------------------------------------------------------------------------- |
| Shift+Tab | 既定のキー。Ogura を選んでいる間はアプリに渡りません                                                                                     |
| Ctrl+/    | MS-IME にも macOS 標準にも割り当てがない組み合わせ。Shift+Tab をアプリに渡したい人向け                                                           |
| F19       | 普通のキーボードにはないキー。キーボードのファームウェアや [Karabiner-Elements](https://karabiner-elements.pqrs.org/) で、親指の近くなど好きなキーに割り当てて使います |


3 つのキーは設定の「詳細」タブのチェックボックスで個別にオン・オフできます。既定はすべてオンです。機能自体を使わないときは同じタブの「続きを書く」を「オフ」にします。

## モデルを選ぶ

設定 > 詳細 > 続きを書く で切り替えます。


| 選択肢            | 向いている人                  | 必要なもの                                |
| -------------- | ----------------------- | ------------------------------------ |
| Apple の端末内モデル  | 何も用意したくない。まず試したい        | macOS 26 以降、Apple Intelligence オン    |
| Mac 内の MLX モデル | もっと賢く、もっと速く。モデルを自分で選びたい | Apple Silicon、モデルのダウンロード（0.9〜3.3 GB） |


MLX モデルは [MLX](https://github.com/ml-explore/mlx) 形式（`config.json`、`safetensors`、`tokenizer.json`）のフォルダを Ogura のモデル置き場に入れると選べるようになります。置き場は設定の「モデルのフォルダを開く」で開けます。Ogura 自身は通信しないので、取得は IME の外で行います。ソースにあるスクリプトが Hugging Face から取ってきて置き場に入れます。

```bash
Tools/download_continuation_model.sh                                   # 既定: LFM2.5-1.2B-JP
Tools/download_continuation_model.sh mlx-community/Qwen3.5-2B-4bit     # 別のモデル
```

手元（M 系 Mac）で試した結果を以下に示します。読み込みは最初の 1 回だけ、生成は読み込み済みのときの 1 回あたりの時間です。


| モデル                                                | 大きさ    | 読み込み  | 生成        | 試した印象                                                 |
| -------------------------------------------------- | ------ | ----- | --------- | ----------------------------------------------------- |
| `mlx-community/LFM2.5-1.2B-JP-202606-OptiQ-4bit`   | 0.9 GB | 0.3 秒 | 0.1〜0.2 秒 | 日本語特化。簡潔で自然、敬体・常体を文脈に合わせる。英語も書ける。まずこれ                 |
| `mlx-community/sarashina2.2-3b-instruct-v0.1-4bit` | 1.9 GB | 1.6 秒 | 0.3〜0.5 秒 | 日本語が最も自然で、内容も具体的。長く書きたがるので 3 文で切って使う。メモリを 2 GB ほど使う   |
| `mlx-community/TinySwallow-1.5B-Instruct-4bit`     | 0.9 GB | 1.8 秒 | 0.1〜0.4 秒 | 日本語は自然だが、Markdown の記号や「\[ユーザー\]様」のような穴埋めが混じることがある     |
| `mlx-community/Qwen3.5-2B-4bit`                    | 1.7 GB | 0.6 秒 | 0.1 秒     | 英語が得意。日本語はやや硬く、中国語の漢字（听、など）が混じることがある                  |
| `mlx-community/gemma-4-e2b-it-4bit`                | 3.3 GB | 2.7 秒 | 0.1〜0.2 秒 | 日本語が自然で、文脈の固有名詞や用件をよく踏まえた続きを書く。英語は短め。メモリを 3.5 GB ほど使う |


英字モード（入力メニューの「英字」）でも同じキーで使えます。カーソルの前の文章が英語なら、指示も英語に切り替えて続きを書きます。

[mlx-community](https://huggingface.co/mlx-community) にある `*-4bit` のテキストモデルなら、だいたいそのまま動きます（対応アーキテクチャは [mlx-swift-lm](https://github.com/ml-explore/mlx-swift-lm) の一覧を参照）。Gemma 4 の E4B（5.2 GB）は試していません。

モデルは最初に使うときに読み込み（上の表の時間）、以降は Ogura のプロセスに載せたままにします。別の入力ソースに切り替えて 5 分たつと、モデルを自動で解放してメモリを空けます。

## うまくいかないとき


| 表示                                      | 意味                                                                                                            |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| （続きを思いつきませんでした）                         | 3 回生成しても使える出力にならなかった。もう一度押すか、少し書き足してから押す                                                                      |
| （Apple のモデルが安全上の理由で続きを書きませんでした…）        | Apple の安全フィルタが反応した。日本語の普通の文でも誤って反応することがある。Ogura は文脈を末尾だけに縮めて 2 回まで自動でやり直し、それでも止められたときにこの表示になる。少し書き足すか、別の位置で押す |
| （モデルが混み合っています…）                         | 端末内モデルを他のアプリが使っている。少し待つ                                                                                       |
| （続きを書くための文章がカーソルの前にありません）               | カーソルの前が空。アプリによってはカーソルの前の文章を Ogura に渡さないものがあり、その場合もこの表示になる                                                     |
| （システム設定で Apple Intelligence を有効にしてください） | システム設定 > Apple Intelligence と Siri でオンにする                                                                  |
| （端末内モデルを準備中です…）                         | モデルのダウンロード中。しばらく待つ                                                                                            |
| （この Mac では Apple の端末内モデルを使えません）         | Apple Intelligence に対応しない Mac か、macOS 15 以前                                                                   |
| （設定の「続きを書く」がオフです）                       | 設定の「詳細」タブで「Apple の端末内モデル」か「Mac 内の MLX モデル」を選ぶ                                                                 |
| （設定の「続きを書く」で MLX モデルを選んでください）           | 「Mac 内の MLX モデル」を選んだがモデルが未選択。モデルを置いて選ぶ                                                                        |
| （モデル「…」を読み込めませんでした）                     | フォルダの中身が MLX 形式でないか、対応していないアーキテクチャ。別のモデルを試す                                                                   |


提案が薄く見えず普通の色で出るアプリがあります。これはアプリ側が入力中の文字の色指定を無視しているためで、Tab / Esc の動きは変わりません。

## 仕組み

- **モデル**: Apple の Foundation Models か、Mac に置いた MLX モデル（[mlx-swift-lm](https://github.com/ml-explore/mlx-swift-lm) で実行）を使います。Apple のモデルには「渡された文章の直後に自然につながる 1〜2 文（80 文字以内）だけを書く。文章を繰り返さない。文体と話題を合わせる」と指示します。MLX モデルには返答の先頭に書きかけの文章を置き、「出力の冒頭にある文章はあなた自身がここまでに書いたもので、その末尾の直後から同じ文章を書き進める」と指示します。こちらには文数や文字数の数字を入れません。小さいモデルは数字や「書きかけ」「ユーザー」という語を復唱して、「（80文字以内）」と但し書きを付けたり「書きかけの文章を渡してください」と返したりするためで、18 の文脈 × 4 モデルの計測では指示の復唱が 26% から 13% に減りました。推論モデル（Qwen3 など）は思考を切って呼びます。
- **繰り返しの除去**: 端末内モデルは続きを頼んでも直前の文章をなぞってから書き始めることがあります。文脈の末尾と提案の先頭で重なる部分を削ってから表示します。言い回しを少し変えてなぞり直したとき（「来月の初めまでに」を「来月の初めに」と書くなど）も、文脈の末尾の句まで似ていればそこまでを削ります。文脈のどこかにある言い回しを丸写しと見るのは 4 文字相当以上の文だけで、「です。」のような短い語尾は、文脈の末尾と重なっていなければ残します。
- **安全フィルタへの対処**: Apple のモデルは安全フィルタで生成を止めることがあり、英語の "Content Likely Unsafe" を返します。Ogura はこれを日本語の知らせに置き換え、文脈をカーソル直前の 1/4 に縮めてやり直します（最大 3 回。フィルタは文脈のどこかに反応していることが多く、縮めると通ることが多い）。
- **壊れた出力のやり直し**: 直前の文章の丸写し（文脈の末尾 150 文字と本文の文字で 16 文字以上重なる、文章全体と 24 文字以上重なる、または文脈の末尾の句そのもの）、同じ文の繰り返し、同じ語句の繰り返し（16 文字以上なら 2 回、8 文字以上なら 3 回）、空の出力、記号だけの出力（「））」など。句点だけは文を閉じる続きとして許します）、会話形式の制御トークンの形（`<|` や `|>` を含む出力）、続きではなく指示について語る出力（「書きかけの文章を渡してください」「80文字以内で書き足します」「[ここに続き]」のように、小さいモデルが指示を復唱したもの）は壊れたものとして捨て、最大 3 回まで自動で生成し直します。3 回とも壊れていたら止まります。無限にはやり直しません。長さはかなと漢字（英語ならラテン文字）だけで数えるので、製品名や数字の引用、「ありがとうございました」のような決まり文句は壊れた出力になりません。文脈そのものがその言い回しや角括弧を含んでいるとき（この機能の説明文や Markdown を書いているときなど）は、指示について語っているとは見なしません。長いメールの結びの決まり文句が本文の前の方にもあるだけでは丸写しになりません。
- **MLX モデルの生成の調整**: 返答の先頭に書きかけの文章を置く形式では、文章が「。」で終わっているとモデルがそこで返答を終えてしまうことがあります（Gemma 4 で頻発）。最初の 2 トークンでは返答の終わりを選ばせず、必ず何か書き足させます。文章が句読点で終わっているときは、句読点や空白だけのトークンも最初の 2 トークンでは選ばせません。終わりだけを禁じると次の候補の「。」が選ばれて「。。」になるためです（sarashina などで起きていました）。それでも続きの先頭に句読点が来たら、表示する前に落とします。上限（120 トークン）で切れた出力は、最後の完結していない文を落として表示します。 40 文字以下の短い文章は、返答の先頭に置くだけでなく依頼にも添えます。「了解しました。」のような文章を返答の先頭に置くだけだと、モデルがそれを依頼への自分の返事と取って「どのような文章を書きますか」と聞き返し、3 回とも壊れて知らせになっていました（短い文脈 14 件の計測で、Gemma 4 の知らせが 25% から 2% に減りました）。それでも sarashina は、返事に見える短い文章では文章の書き方について語り出すことが多く、知らせになりやすいです。その場合は少し書き足してから試してください。 モデルの会話形式の制御トークン（Gemma 4 の `<|channel>`／`<channel|>`、`<think>` など。手番の終わりを示すものは除く）は、生成中ずっと選ばせません。返答の冒頭に書きかけの文章を置く形式では、短い行が並ぶ文脈でモデルがその文章を自分の思考と見なし、思考の区間を閉じる印を出してから文脈の文を言い直すことがあり、その印が文字として表示されていました。出力に残った印は表示する前に除きます。
- **表示の後始末**: 提案や知らせを表示したまま別のキーを押したり、クリックやフォーカスの移動で入力が確定したりしたときは、その場で表示を消します。消し忘れるとアプリが薄い表示を本文として確定してしまい、次に読む文脈に前の提案や「（続きを思いつきませんでした）」が混ざって、以後どのモデルでも続きが出なくなります。 提案を受け入れるときは、薄い表示を本文で置き換える形で入れ、先に消してから入れ直すことはしません。先に消すと、アプリによっては直前に確定した文章が下線付きの入力中の扱いに戻り、提案で置き換えられてしまうことがあるためです。
- **読む範囲**: このキーを押したときに限り、カーソルの前の最大 400 文字をアプリから読みます。それ以外のときは通常の変換と同じ 30 文字までです。読んだ内容はモデルに渡すだけで、保存も送信もしません（[データの扱い](privacy.md)を参照）。

モデルは短い文章向けで、長い論旨を組み立てるのは得意ではありません。1〜2 文ずつ、出し直しながら使うのが向いています。
