# 半角英字の識別

Ogura は、ローマ字入力のまま打った英単語、製品名、コードの名前を見分けて、半角英字のまま変換します。この文書では、その見分け方を説明します。

## 何を解決するか

ローマ字入力で `github` と打つと、ふつうの日本語入力は「ぎてゅb」のように読みます。英字にするには、英数モードに切り替えるか、変換のあとで英字に直す必要があります。英語や専門用語の混じった文章では、この切り替えが何度も要ります。

Ogura は、打ったキーの並びのうち、どこが英単語でどこがローマ字かを見分けます。

| 打ったキー | 変換 |
| --- | --- |
| `kyouhagithubnipushsita` | 今日はGitHubにpushした |
| `korehaOguradesu` | これはOguraです |
| `Sakehasakedesu` | Sakeは酒です |
| `iphonenoapuri` | iPhoneのアプリ |
| `tatoebawindowstokakeba` | 例えばwindowsと書けば |

難しいのは、同じキーが英単語にもローマ字にも読めることです。`token` は英単語にも「とけん」にも読めます。`sake` は英単語にも「さけ」にも読めます。綴りだけでは決まらず、前後の語や文の意味で決まります。

## 判断の約束

- **Shift で打った大文字は英字のしるし**: 大文字から打った語は、日本語に読めても英字にします（`Kyouha` は Kyouは）。Shift を押すのは、英字で書きたいときだからです
- **ローマ字として成り立つなら、迷ったら日本語**: 日本語入力なので、小文字で日本語に読める語は日本語が基本です（`sakewonomu` は「酒を飲む」）。日本語として読むと不自然なとき（`tokenwookuttekudasai` を「都県を送ってください」と読むなど）や、前後から英単語らしいときは英字にします
- **迷う語は変換エンジンに任せる**: 英単語とも日本語とも読める小文字の語は、その確からしさを付けて、かな漢字変換エンジンの辞書と文脈に決めてもらいます（後述）

## 仕組み

### 系列ラベリングとして解く

Ogura は、打ったキーの一つ一つにラベルを付ける問題として解きます。ラベルは三つです。J はローマ字のキー、B は英単語の最初の文字、I は英単語の 2 文字目以降を表します。

```
keys:   k y o u h a g i t h u b n i p u s h s i t a
labels: J J J J J J B I I I I I J J B I I I J J J J
```

B から、次の B か J の手前までが一つの英単語です（この例では github と push）。J のキーはローマ字として、かな漢字変換エンジンに渡します。

並んだ要素の一つ一つにラベルを付ける問題を、系列ラベリング（sequence labeling）と呼びます。文章から人名や地名を抜き出す固有表現抽出、日本語や中国語の単語分割、品詞の付与も同じ形の問題で、よく研究されています。B と I でひとまとまりを表すラベルの付け方も、固有表現抽出で広く使われているものです（BIO 方式）。

### 一般的な手法

系列ラベリングの代表的な手法を挙げます。

| 手法 | 考え方 | 向き不向き |
| --- | --- | --- |
| 辞書と規則 | 知っている語を探し、綴りの規則で決める | 速く、振る舞いを説明しやすい。知らない語や、英単語とも日本語とも読める語には、場合ごとに規則を足すことになる |
| 隠れマルコフモデル（HMM） | ラベルのつながりと、ラベルごとの文字の出やすさを確率で表す | 学習が簡単。「辞書にある語か」のような、互いに重なり合う手がかりを足しにくい |
| 条件付き確率場（CRF） | 各キーの手がかりの重みと、隣り合うラベルのつながりの重みを足して、ラベル列全体に点数を付ける | 手がかりを自由に足せる。最良のラベル列も各ラベルの確率も、動的計画法で正確に求まる |
| semi-Markov CRF | CRF のキーごとの点数に加えて、区間（ここでは英単語の候補）にも点数を付ける | 語全体の手がかり（辞書にある語か、語全体が英語らしい綴りか）を使える。区間の長さには上限が要る |
| ニューラルネットワーク（BiLSTM、Transformer） | 文字の並びから手がかりそのものを学ぶ。出力に CRF を重ねることも多い（BiLSTM-CRF） | 精度を上げやすい。モデルが大きく計算が重くなりやすく、判断の理由を説明しにくい |

Ogura は2種類の実装をしています。「規則による識別」は一つ目の手法です。「学習モデル」は、semi-Markov CRF にBiLSTM を足したものです。

### この手法を選んだ理由

- **キーを打つたびに判断する**: 打つたびに入力全体を見直すので、一回の判断を数ミリ秒で終える必要があります。CRF の点数は手がかりの重みを足すだけで計算でき、補正のネットワークも小さくしています
- **語の単位で考える**: 英単語かどうかは、語全体を見て初めて決まることが多いので、区間に点数を付ける semi-Markov CRF にしています
- **外からの手がかりを足せる**: かな漢字変換エンジンによる日本語としての解析や、英単語と製品名の一覧を、そのまま手がかりに使えます
- **確率が出る**: 英単語の候補それぞれが正しい確率を計算できるので、迷う語を見つけて変換エンジンに任せられます（後述）

### キーの並びの区切り方に点数を付ける

入力は、打ったキーの並び（大文字・小文字を含む）です。ラベルの付け方は、キーの並びを「ローマ字のキー」と「英単語」に分ける区切り方と一対一に対応します。Ogura は、区切り方それぞれに点数を付け、最も点数の高い区切り方を選びます。

点数は、キーごとの点数と、英単語の候補ごとの点数の和です。キーごとの点数は、そのキーに J、B、I のそれぞれを付けたときの点数です。英単語の候補（`github`、`githubni` など、ありうるすべての範囲）には、語全体としての点数が付きます。区切り方の数はキーが増えると急に増えますが、動的計画法（Viterbi アルゴリズム）で最良のものを数ミリ秒で選べます。それぞれの英単語の候補が正しい確率も、同じような計算（前向き・後ろ向きアルゴリズム）で出せるので、後で迷う語を見つけるのに使います。

### 何を手がかりにするか

キーごとの手がかり:

- 前後の文字の並び
- 大文字かどうか
- そこまでのキーがローマ字として読めるか（`gith` の `th` はローマ字にならない）
- ローマ字が読み残す文字か。`ko-hi-map-1` の `p` は、後ろに `-` が続くので、かなにならないまま「こーひーまpー1」に残ります。ローマ字で読み残しになるのは打っている途中の最後の文字だけなので、途中に残る文字は、その辺りが英単語であるしるしです
- 文字の並びの統計: ローマ字らしい並びか、英語の綴りらしい並びか。ローマ字と英語、それぞれの文字の並びの出現頻度から計算します
- そのキーを含む部分を日本語として読むとどうなるか。かな漢字変換エンジンで入力を日本語として解析し、一つの語になるか、品詞は何かを見ます。`hoteru` は「ホテル」という一語に読めますが、`apocalypse` は日本語として読むと文字が余ります

英単語の候補ごとの手がかり:

- 知っている英単語や製品名か。知っていれば正しい綴りも使います（`iphone` を iPhone と書く）
- 語全体として英語らしい綴りか
- 後ろで日本語の語（助詞など）が始まるか
- その範囲を日本語として読むと、ちょうど一語になるか
- ハイフンでつないだ語（`e-mail`、`built-in`）は、ハイフンを含めて一つの英単語の候補になります。一覧にある語か、一文字の部分があるか（`e-mail` の `e`）も見ます
- その綴りをかなで読んだときに辞書にある名詞が、どれだけよく使われる語か。助詞や助動詞としても読めるか。`token` の「とけん」には珍しい「都県」しかなく、`sake` の「さけ」はよく使う「酒」、`node` の「ので」は助詞です

それぞれの手がかりの重みは学習で決めます。手がかりの種類は膨大なので、ハッシュで約 100 万の枠に割り当て、枠ごとに重みを持たせています（モデルの `tagger.bin`、16 MB）。

### ニューラルネットワークによる補正

線形の重みの和では捉えにくい手がかりの組み合わせを補うため、小さなニューラルネットワーク（双方向 LSTM、隠れ層 64）が同じ手がかりを読み、線形モデルの点数に補正を足します（`neural.bin`、0.3 MB）。BiLSTM-CRF に近い形ですが、主役は線形の CRF で、ネットワークはその補正です。

補正のネットワークは、線形モデルが間違えるところを学ぶように訓練しています。そのために、学習データを二つに分け、一方で学習した線形モデルの点数を他方のデータの上で計算して、その点数を入力にします。線形モデルが学習で見ていない文での点数なので、実際の入力での間違え方に近くなります。補正は特に、打っている途中の表示の揺れを減らします。

### 打っている途中の入力

キーを打つたびに見分け直すので、モデルは打ちかけの入力も扱います。学習データの半分は、文を途中で切ったものです。

学習データには実際の入力より英単語が多く含まれます。そのままでは英字に寄りすぎるので、判定のときは、小文字だけの英単語の候補と、まだ打ち終わっていない英単語の候補に、決まった量の点数を引きます。大文字を含む語は Shift が意図を示すので引きません。引く量は、評価とは別の文で選んでいます。

### 文節の区切りとの関係

変換中に Shift+← / → で文節の区切りを英単語の中に動かすと、英単語はその位置で二つに分かれ、両側とも英字のまま残ります。英字の範囲を間違えたときは、文節を縮めて F10 を押すと英字にできます。

## 変換エンジンとの組み合わせ

見分けた結果は、かな漢字変換エンジンに渡す入力に反映します。

- **確かな英単語**: そのキーを「英字のまま打った文字」に置き換えて渡します。変換エンジンは英字をそのまま書き、残りのローマ字をかな漢字に変換します。英単語の中のハイフンも打ったまま（半角の `-`）書きます
- **迷う語**: 小文字で、英単語である確率とローマ字である確率がどちらも 5% を超える語は、キーをローマ字のまま渡し、英字の綴りを一時的な辞書の語として加えます。この語の点数は、英単語である確率と、ローマ字である確率の比から決めます（五分五分なら、あまり使われない語くらいの点数）。こうすると、変換エンジン自身の辞書と、語のつながりの点数で決まります。`sakewonomu` では、辞書の「酒」が sake に勝ちます。`token` と「とけん」が五分五分と判断されたなら、token の点数は辞書の「都県」より良いので token になります
- **Zenzai を使うとき**: Zenzai（ニューラルかな漢字変換）は一時的な辞書の語から作った変換を退けることがあるので、迷う語は先に Zenzai なしの変換で決め、英字に決まった語は確かな英単語と同じく渡します。日本語に決まった語は一時的な辞書の語を外して渡し、Zenzai が自分で英字に書かないようにします（`yamanomine` を打った時点の「山のmine」）
- **迷ったら日本語**: Zenzai を使うとき、英字にしようとしている小文字の語のうち、標準的なローマ字で綴れてかなとしても読めるものは、その語を英字のまま読んだ入力と、ローマ字として読んだ入力を Zenzai に比べさせます。英字の方がはっきり自然でなければ日本語にします（`mineninoboru` の「峰に登る」、`minenimukau` の「峰に向かう」）。Zenzai は語の意味までは分からないので、日本語として不自然な読みも同じくらいの点数になり、`tokenwookuttekudasai` は「と犬を送ってください」になります。日本語入力なので、迷ったときは日本語を選びます。比べるのは打ったところまでの読みで、入力がそこで終わるかどうかは比べません（文末に「ます」を足しただけで結果が変わらないように）。末尾のまだかなになっていない文字も除いて比べます。残っていると英単語の続きのように見え、英字が有利になるからです（`hometekureta` を `homet` まで打った時点で「homet」、`takaimineni` に `n` を打った時点で「高いmineにn」と一瞬見えないように）。この確かめがあるので、Zenzai を使うときは小文字の英単語に引く点数を小さくして、英字になりやすくしています（モデルの decoding.tsv の `checkedWord`）。ただし打っている途中の語（後ろにまだかなになっていない文字しかない語。`yorosikuoneg` の `one`）は確かめられないので、確かめのないときの点数のままにし、途中で英字がちらつかないようにしています
- **不自然な日本語なら英字**: 逆向きの確かめもします。識別層が日本語と読んだ小文字の語でも、英単語として知っている語で、英単語である確率が 0.1% 以上あり、標準的なローマ字で綴れて、後ろに読み終えたかなが続くか入力の終わりにあるもの（迷う語のうち変換エンジンが日本語にしたものも含めます）は、同じように Zenzai に比べさせます。英字で読んだ方が自然なら英字にします（`nodewokidousuru` は「のでを起動する」ではなく「nodeを起動する」）。比べるのは同じく読み終えたかなまでです（`Sakehasakedes` の `s` があると sake を英字と読みやすくなるため）。日本語の方がはっきり自然とまでは言えないときは、Space の候補に英字も出します（`modegakawaru` の「も出が変わる」に「modeが」）
- **標準的なローマ字**: ヘボン式、訓令式、日本式（と外来語の書き方の `she`、`fa`、`ti` など）で綴れない語は、日本語の読みと比べずに英字のままにします。変換エンジンは `co` を「こ」と読みますが、「この子で」を `konocode` と打つ人はいないので、`konocode` の `code` は英単語を打ったものです
- **英単語の終わり**: 学習データには Shift で打った名前（Kanagawa、Ogawa）があるので、大文字から打った語のあとにローマ字が続くと、`Winnogawa` のように名前の続きと読んでしまうことがあります。小文字の語でも、後ろのローマ字まで取り込むことがあります（`sign-inshite` の sign-inshi）。識別層は、語がもっと手前で終わる区切り方（Win、sign-in）にも確率を付けています。その確率が 1% 以上で、短い方が辞書にある語（Win。ハイフンでつないだ語は、それぞれの部分が辞書にある 2 文字以上の語なら sign-in も）で、残り（nogawa）が標準的なローマ字で綴れてかなに読めるときは、語を長いまま読んだ入力と、短い語のあとをローマ字として読んだ入力を Zenzai に比べさせ、後者の方がはっきり自然なら短い語で終わります（`suittihaWinnogawaniarimasu` は「スイッチはWinの側にあります」、`Fannonakamiwomiru` は「Fanの中身を見る」、`sign-inshitekudasai` は「sign-inしてください」）。残りは、短い語のあとからローマ字として読みます。変換エンジンも英字のあとをそう読むからです（`Machakaku` は入力全体では「まちゃかく」ですが、Mac のあとの `hakaku` は「はかく」で、「Macは拡張」になります）。名前はそのままです（`Shinagawaniikimasu` の Shinagawa、`Inouesanni` の Inoue）。短い方を辞書にある語に限るのは、知らない語のあとでは Zenzai も英字とかなを見分けられないからです（`T-shatsu` を T-sha とツに切らないように）。ただし大文字から打った短い方が、変換エンジンの辞書にある日本語の名前なら（Osaka は「大阪」）、Zenzai が後者を少しでも自然と見ればそこで終わります。Zenzai は名前のあとの接尾辞を少ししか好まず（`Osakashi` の Osaka市）、名前を途中で切った読みははっきり嫌う（Yoko|hama、Ino|ue）からです（`watashihaOsakashiniikimasu` は「私はOsaka市に行きます」）
- **英字の語の前後で分けて変換する**: Zenzai は、入力の中に英字があると、そのあとのかなをかなのまま写したり（`Osakashiniikimasu` で Osakaしにいきます）、英字で続けたり（`Kanagawakenn` で KanagawaKen）、人の名前と読んだり（Osaka氏）します。英字で打った地名や人名が、英字のままでは何か分からないからです。そこで、最初の英字の語の前後で入力を分けます。語のあとのかなだけを変換し、語は左の文脈の末尾として Zenzai に渡します。語が辞書にある日本語の名前なら、その名前にして渡します（Osaka なら「大阪」、Kanagawa なら「神奈川」）。名前は、小文字にしたキーをかなに読み、ヘボン式が省く長音も試して（osaka を「おおさか」、tokyo を「とうきょう」）、変換エンジン単体で変換し、読み全体を一語の固有名詞として読める中で最も確からしいものです。Zenzai は「大阪」のあとの「しにいきます」を「市に行きます」と読むので、Osaka市に行きます になります。語の前にかながあれば（`watashihaOsakashi…`）、その部分は先に変換し（名前を右の文脈にして、「はしは」を「橋は」と読めるように）、その変換と語を候補の頭に付けます。入力の先頭の英字の語は名前でなくてもこのように渡し、途中の語は名前のときだけ分けます（それ以外は一度の変換に任せます）
- **変換で反対の読みを選べる**: 迷った語は、どちらに決めても Space の候補の 2 番目に反対の読みを出します。英字にした語は日本語の読み（mineに向かう に「峰に」）、日本語にした語は英字（と犬を送ってください に「tokenを」、も出が変わる に「modeが」）です。大文字から打った語の終わりを迷ったときも同じで、もう一方の終わりで読んだ候補を出します（Winの側にあります に「Winnogawaに」）
- **英字で書かれたカタカナ語**: 変換エンジンの辞書はカタカナ語を英字で書くことがあります（`uindouzu` のウインドウズを Windows）。英字は打ったところにだけ出るべきなので、そうした語は読みのカタカナで書きます

## 学習データ

二種類の文を、さまざまなローマ字の打ち方（`shi` と `si`、`tsu` と `tu`、「ん」の打ち方など）でキーの並びにして学習します。

- **辞書から作った文**: Mozc（Google 日本語入力のオープンソース版）の辞書の単語と語のつながりの点数から日本語文を作り、名詞の一部を英単語、製品名、カタカナ語に置き換えます
- **言語モデルに書かせた文**: 言語モデルに、英単語や製品名を使った日本語文、話題だけを与えた日本語文、カタカナ語を使った日本語文を書かせます（約 21 万文）。読みは形態素解析で付けます。辞書から作った文より、実際に書かれる文に近くなります

英単語と製品名の一覧は、man ページ、Homebrew のパッケージの名前と説明、英単語の辞書、アプリの名前などから作ります。Ogura に入れる一覧は、公開されている資料（macOS・Xcode・Linux と Homebrew でよく入れられているツールの man ページ、英単語の辞書、Homebrew のパッケージの一覧、macOS 標準アプリの画面の文言、オープンソースのアプリと文書の日本語訳、Debian のパッケージの説明、Wikipedia 日本語版の見出し、Mozc の辞書）から作り、モデルの学習に使った語彙の範囲に絞ります。学習のときに知らなかった語を知っていることにすると、モデルの読みが変わるためです。

辞書から作った文には、実際の入力で出会うのに辞書の文からは出にくい形も混ぜます。

- **ハイフンでつないだ英単語や数字**（`map-1`、`e-mail`、`built-in`、`3-2-1`）: ローマ字では `-` が長音なので、これがないとハイフンの近くの英字をローマ字と読みやすくなります。英字どうしをつなぐ語は、man ページや Homebrew のパッケージの説明、アプリの画面の文言から集めた実際の語（約 2,500 語）を使い、ハイフンも含めて一つの英単語として学習します。一覧にない、英単語二つをつないだ語（`us-west`）も混ぜます。これがないと、ハイフンの前の短い語の一文字目を前の日本語の続きと読むことがあります（`us-westhadoudesuka` の「うs-west」）。言語モデルに書かせた文の `Wi-Fi` のような語も同じく一つの英単語にします
- **言語や国のコードから始まる語**（`eu-west-1`、`us-east`、`en-US`）: macOS のロケール名にある言語と国のコード（ja、en、eu、US、JP など）を、英単語や数字とハイフンでつなぎます。これがないと、ハイフンの前の短いコードの一文字目を前の日本語の続きと読むことがあります（`depuroisakihaeu-eastdesu` の「絵u-east」）
- **英字とカタカナで書く語**（「Tシャツ」「Jリーグ」「QRコード」）: 辞書にある語を、英字のあとに、ときにハイフンを挟んで、カタカナの部分をローマ字で打つ形にします（`T-shatu`、`Jri-gu`）。英字とハイフンのあとに英単語が続く例（`T-shirt`、`e-mail`）しかないと、`T-shatu` の `sha` まで英単語と読んでしまいます
- **長音で終わるカタカナ語の直後の英単語**（`コーヒーmap`）
- **英字で打った地名と、日本語の接尾辞**: 辞書には「神奈川県」「横浜駅」「東京都」のように接尾辞まで含んだ地名があります。英字で打つのは名前の部分で、接尾辞は日本語で打つので（`Kanagawakenn` で Kanagawa県）、そのように学習します。ひとつの英単語（Kanagawaken）として学習すると、大文字から打った名前のあとのローマ字を名前の続きと読んでしまいます
- **英単語と同じ綴りになる名詞**（「峰」の `mine`、「竹」の `take`）を、日本語の文で使われる多さに合わせて

言語モデルに書かせた文は、学習の前に二つの偏りを直します。

- **ローマ字書きの日本語**: 言語モデルに英字で書かせた日本語の語（`sake`、`sushi`、`anime` など）は、小文字で打てば日本語という約束に合わせ、ローマ字として学習します
- **英単語らしく見える語の多さ**: 日本語にも読める英単語（`mine`、`token`、`kite` など）を使わせた文は、語を均等に選んで書かせたため、めったに英字で書かれない語（`mine`）まで技術用語（`token`）と同じだけ英字の例がありました。こうした文は、その語が実際に使われる多さ（辞書から作った文で英単語を選ぶときと同じ重み）に合わせて間引きます

学習は、二つに分けたデータそれぞれで線形モデルを学習して平均し、その上に補正のネットワークを学習します。

## 評価

評価は、文を 1 キーずつ打って Enter で確定し、英字の部分が正しいかで数えます（Zenzai を使用）。

| 評価の文 | 規則 | 学習モデル |
| --- | --- | --- |
| 手書きの 70 文 | 63 | 70 |
| アプリの画面の文言から作った文のうち、英単語を含む 386 文 | 282 | 380 |
| 同じく日本語だけの 246 文（英字を誤って出さないか） | 244 | 244 |
| 英単語を含む文で、打っている途中に英字とかなの表示が入れ替わる文の割合 | 59% | 11% |

評価に使った文と、学習と評価の道具は、このリポジトリには含めていません。アプリの画面の文言から作った文は、文言がアプリのものだからです。

1 打鍵あたりの時間は、中央値で規則 4.6 ms、学習モデル 3.8 ms、遅い方から 5% の打鍵で規則 31 ms、学習モデル 13 ms です（Zenzai と、日本語の読みの確かめを含む）。

## 苦手なこと

- **意味で決まる小文字の語**: `manpe-ji`（man ページ）、`matchishita`（マッチした）のように、英単語とも日本語とも読める語は、文の意味で決まります。Zenzai は意味まで分からないので、迷ったら日本語にします。そのため英単語のつもりでも日本語になる文（`tokenwookuttekudasai` の「と犬を送ってください」、`ratewoageru` の「ラテをあげる」）があります。Space の候補で英字を選ぶか、Shift で打てば英字になります
- **ハイフンでつないだ語の一部が日本語として自然なとき**: `open-source` の `source` のように、つないだ語の一部がローマ字としても自然に読めると、その部分を日本語と読むことがあります
- **大文字から打った知らない語の終わり**: 知らない語は、どこまでが英単語かを決めにくいことがあります（`Targafairu` を Tarが…にしてしまう）
- **一文字ずつの判断の揺れ**: 打っている途中では、語の最後まで打つまで判断が決まらず、表示が一時的にかなと英字の間で入れ替わることがあります

間違えたときは、F10（英字）や F7（カタカナ）、文節の区切りの調整で直せます。

## 設定

学習モデルによる識別は試用中です。設定の「入力」タブの「英単語とローマ字の見分けに学習モデルを使う」で有効にします。オフのときは、これまでの規則で見分けます。その場合はMozc の英字候補の仕組みを参考に、知っている英単語と、大文字から打った語を英字にします。
